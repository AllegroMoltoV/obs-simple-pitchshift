# v1.1.0 の検証

2026-11-08 に、処理窓の選択、フォルマントとゲインのスライダー、0.1 刻みの半音を追加した v1.1.0 を検証した。作者のユーザーテストを経て採用した。事前の調査結果を [事前調査](2026-11-08-v110-investigation.md) に記載している。

## 変更内容

| 項目 | 内容 |
|---|---|
| 処理窓 | 20 / 30 / 40 ms から選択、既定 40 ms。設定キー `window_ms` |
| 更新間隔 | 各処理窓の 1/4 |
| 半音 | -12.0〜+12.0、0.1 刻み。設定キー `semitone` を維持 |
| フォルマント | -12.0〜+12.0 半音、0.1 刻み。設定キー `formant` |
| ゲイン | -30.0〜+30.0 dB、0.1 刻み。設定キー `gain`。ピッチ処理の後段で全チャンネルへ適用 |
| 処理器 | 2 つのサンプルレートと 3 つの処理窓の計 6 個をフィルター生成時に準備 |

処理状態の初期化を、処理窓の変更、再有効化、サンプルレートの変更、バイパスからの復帰に限定した。半音、フォルマント、ゲインの変更では初期化しない。バイパスの条件は、半音とフォルマントがともに 0 の場合である。

## 処理窓の選定

当初は 10 / 20 / 40 ms を候補とした。依存ライブラリの `configure` に処理窓の下限は無く、遅延は処理窓と等しい。初回のユーザーテストで、作者が 10 ms と 20 ms を製品品質に達しないと評価した。選択肢を 20 / 30 / 40 ms に変更し、20 ms は音質低下を承知で使う選択肢として残した。表示名は作者が指定した。

| 値 | 日本語の表示名 | 英語の表示名 |
|---|---|---|
| 20 | 20 ms (低遅延・低品質) | 20 ms (low latency, low quality) |
| 30 | 30 ms (やや低遅延・やや低品質) | 30 ms (slightly low latency, slightly low quality) |
| 40 | 40 ms (既定) | 40 ms (default) |

## 検証方法

`tests/pitch-obs-probe.cpp` を拡張し、Windows 11 と OBS Studio 33.0.1 の libobs で、44.1 kHz と 48 kHz の代表音声を処理した。プラグインを読み込んだ隔離環境で、フィルターの出力とタイムスタンプを取得する。

## 検証結果

両サンプルレートで全項目に合格した。

| 対象 | 結果 |
|---|---|
| 半音 -12、-3、0、+3、+12 | 有限値、全フレーム処理、設定復元、タイムスタンプの整合を確認。0 半音は入力と一致 |
| 処理窓 20 / 30 / 40 ms | タイムスタンプの補正量が 20.000 / 30.000 / 40.000 ms と一致。設定を復元 |
| v1.0.0 形式の設定 | 整数の半音 3 を読み込み、処理窓 40 ms、フォルマント 0、ゲイン 0 dB として動作 |
| 半音 2.5 | 保存と復元に成功。単音の周波数を診断値として記録 |
| 半音 0、フォルマント +3 | ピッチ処理を通し、遅延補正 40 ms |
| ゲイン ±6.02 dB、バイパス時 | 入力の 2 倍または 1/2 との最大誤差 0 |
| ゲイン +6.02 dB、半音 +3 | ゲイン 0 dB の出力の 2 倍との最大誤差 0 |
| 半音 +3 から -3 への変更 | 初期化せず処理中の音声が流れ切り、後半が無音 |
| 処理窓 40 ms から 20 ms への変更 | 出力が完全に無音、遅延補正 20 ms |
| 半音 0 でフォルマントが 0 を跨ぐ変更 | 有限値と全フレーム出力。0 へ戻すと入力と一致 |
| 半音 3.0 から 5.0 へ 0.1 刻みで 20 回変更 | 有限値、全フレーム出力、タイムスタンプの整合 |

処理時間は、OBS への送信を含めて入力 1 秒あたり約 0.017 秒だった。処理窓による差は見られなかった。

[PR #5](https://github.com/AllegroMoltoV/obs-simple-pitchshift/pull/5) の最終コミット `1f2fc91` で、Windows、macOS、Linux のビルド、書式検査、Windows 配置検証の CI が成功した。macOS と Linux の実機動作は未確認である。

## ユーザーテスト

作者が通常の OBS Studio に候補を導入し、話し声と歌声で処理窓、半音、フォルマント、ゲインを操作した。初回に処理窓の選択肢を変更し、再テストで採用した。

## 遅延の調査

窓長以外に生じる遅延を確認するため、48 kHz、処理窓 10 ms の候補で、入力から最終ミックスまでの実時間を条件ごとに 8 回測定した。条件は、ピッチ処理を通さない場合、タイムスタンプを補正する場合、補正しない場合の 3 つである。

| 条件 | OBS のバッファー追加なし | OBS のバッファー追加 42 ms |
|---|---|---|
| ピッチ処理なし | 約 19 ms、2 回 | 46〜52 ms、6 回 |
| 補正あり | 12〜14 ms、1 回 | 26〜46 ms、6 回 |
| 補正なし | 19〜25 ms、5 回 | 46〜47 ms、3 回 |

OBS の音声バッファーの追加は、ピッチ処理を通さない条件でも発生した。同じバッファー量で比べると、補正ありの出力が補正なしより約 10 ms 早かった。

## 考察

補正ありでは、処理窓の遅延が OBS の既存のバッファーに吸収されていると考えている。補正をやめると遅延がバッファーに上乗せされるため、補正を維持した。8 回の測定では、補正の有無によるバッファー追加の頻度の差を判定できなかった。プラグインが処理窓以外の遅延を加える処理は見つからなかった。

## 限界

本検証は代表条件の動作と作者の使用感を対象とする。すべての声質、歌唱、音声デバイス、OBS 設定に対する音質と遅延の保証ではない。遅延の測定は音声デバイスへの出力を含まない。入力音声と個人環境のパスを含む生データを公開文書に含めていない。コード読解による厳密な人間レビューは実施していない。
